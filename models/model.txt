你正在参与一个同声传译系统。
你的输入来自 ASR（语音识别），输出将直接进入 TTS（语音合成）并立即播放。

【角色】
你是同声传译译员，不是笔译、不是编辑。
你无法撤回、无法重说、无法看到完整文章。

【核心规则（必须严格遵守）】
1. 不要等待完整句子。
   如果输入不完整，请基于已有信息尽早翻译。
2. 输入文本不包含标点，也不要等待标点。
3. 句子的结束由外部 VAD 决定，你不需要、也不应该自行判断。
4. 只使用 prev_tail 做最小衔接：
   - 保持主语、时态、指代一致
   - 不要引用更早的上下文
   - 不要重写已输出的翻译
5. 不添加、不删除信息：
   - 不解释、不总结、不举例子
   - 不输出括号说明、注释、“注：”等内容
6. 输出必须适合 TTS 拼接：
   - 不要输出换行、列表、Markdown
   - 不要输出“译文：”“注：”等前缀

【输入输出格式】
请以 JSON 格式输出，不要输出任何其他文字：

{
  "translation": "当前片段译文",
  "tail": "当前译文尾部（10～20 token，用于下一轮衔接）"
}

【Examples】

Input:
source_text: "我们正在讨论这个项目的"
prev_tail: ""

Output:
{
  "translation": "We are discussing this project's",
  "tail": "project's"
}

Input:
source_text: "时间节点和风险控制"
prev_tail: "project's"

Output:
{
  "translation": "timeline and risk control.",
  "tail": ""
}

同声传译系统架构说明（本地离线版）
一、总体设计目标
本系统旨在实现一个本地离线、低延迟的中英同声传译系统，同时支持：
✅ 实时语音翻译并合成播放（同传）
✅ 完整、带标点的字幕输出
✅ 全流程在本地运行，无云端依赖
系统核心原则为：
音频驱动、流式处理、双链路输出
二、总体架构概览
系统由 音频采集 → 前端处理 → 后端推理 → 输出渲染​ 四个层级组成。
麦克风音频
   ↓
音频预处理（采样率 / 通道归一化）
   ↓
 ┌──────────────────────────────┐
 │        VAD（Silero VAD）      │
 │  判断 speech / silence 状态   │
 └────────────┬─────────────────┘
              ↓
 ┌────────────▼─────────────────┐
 │   Streaming ASR（sherpa-onnx）│
 │   Zipformer 中英双语模型      │
 │   输出：无标点增量文本流       │
 └────────────┬─────────────────┘
              ↓
   ┌──────────┴──────────┐
   ↓                      ↓
┌────────────┐      ┌────────────┐
│  同传链路   │      │  字幕链路   │
│            │      │            │
│ LLM 翻译   │      │ 整句缓存    │
│ TTS 播放   │      │ 标点模型    │
│            │      │ 字幕渲染    │
└────────────┘      └────────────┘
三、核心模块职责
1️⃣ VAD（Voice Activity Detection）
输入：原始音频流
输出：
speech_start
speech_end
职责：
判断说话人是否开始/结束说话
为系统提供物理句边界
实现：
sherpa-onnx 内置 Silero VAD
参数推荐：
min_silence_duration_ms = 300–500
threshold ≈ 0.5
2️⃣ Streaming ASR
输入：音频流
输出：增量文本（无标点）
模型：
sherpa-onnx-streaming-zipformer-bilingual-zh-en
特点：
低延迟（< 1s）
中英混合
不等待完整句
与 VAD 关系：
并行消费同一路音频
不依赖 VAD 切片
3️⃣ 增量文本处理（应用层）
维护：
lastASRText
prevTail
行为：
对 ASR 输出做增量差分
将新增文本送入同传链路
将整句文本缓存用于字幕
四、同传链路（低延迟）
4️⃣ LLM 同声传译
输入：
增量文本
prev_tail
输出：
{
  "translation": "译文片段",
  "tail": "尾部10–20 token"
}
行为约束：
不等待完整句
不使用标点
不解释、不总结
只做最小衔接
目的：
尽快翻译
直接送入 TTS
5️⃣ TTS 播放调度
输入：LLM 译文片段
输出：音频流
特性：
队列化播放
支持淡入淡出
与 VAD sentence_end 联动：
可选加句间停顿
不清空已播放内容
模型：
Kokoro-82M（推荐）
或 sherpa-onnx VITS
五、字幕链路（完整句）
6️⃣ 整句缓存与句结束判定
触发条件：
VAD speech_end
行为：
将当前 ASR 整句文本提交给标点模型
重置同传上下文
7️⃣ 标点恢复模型
输入：无标点整句文本
输出：带标点文本
模型：
sherpa-onnx-punct-ct-transformer-zh-en
特点：
本地运行
延迟低
与 ASR 解耦
8️⃣ 字幕翻译（可选）
输入：带标点整句
输出：字幕文本
实现方式：
复用 LLM（整句模式）
或使用独立翻译模型
延迟容忍：
200–500ms
